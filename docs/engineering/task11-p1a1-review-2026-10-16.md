## 2. What caused the overhead, and the selected improvement

Attribution of P1-A compact JSON:

| Structure | Bytes, approximately | Finding |
|---|---:|---|
| Evidence mappings | 201,399,387 | 395,271 mapping records repeat long named buffer IDs and field names. |
| Section `source_spans` | 49,910,037 | Repeats source spans also present in section traces. |
| Section `source_trace` | 56,974,324 | 219,528 fragments retain IDs, exact/region precision and synthetic/unmapped lists. |
| Buffer registry | 30,044,388 | Native candidates, native block text and raw/cleaned/canonical/section buffers. |
| Buffer text itself | 27,443,261 | Only 21,807 bytes are exact duplicate whole-buffer text values. |

Component measurements include small JSON wrappers and are attribution estimates, not an exact additive partition. Mappings account for about 58.6% of compact JSON; the two section provenance representations together account for about 31.1%.

Evaluated options:

- Shared immutable whole-text buffers: little exact-text deduplication benefit here; changing mutable in-memory models introduces broader compatibility work. Overlapping text views could save more, but require a new view/mapping contract.
- Reference-based/lazy section traces: could remove substantial expanded duplication and improve load memory, but changes current direct consumers and persisted trace hydration. Deferred rather than silently removing data.
- Compact JSON alone: measured P1-A 343.54 MB versus actual indented 450.00 MB; inadequate as the main improvement.
- Lossless gzip: P1-A compact JSON alone compressed to 14.89 MB in the initial evaluation. Selected as the smallest persistence-only improvement. The actual versioned JSON envelope adds base64 overhead and the new warning metadata, yielding 20.12 MB.

The new `gastroagi-source-map-gzip-json-v1` envelope retains document identity fields at the JSON root, including `content_hash` used by existing output reuse checks. Its payload contains **every field of the complete SourceDocument**, streamed through deterministic gzip level 6 (`mtime=0`), then base64 encoded. The envelope records expanded byte length and SHA-256. No candidates, buffers, mappings, deletions, trace precision, warnings or section text are discarded or reconstructed on read-back.

Serialization splits the large evidence registry and streams mapping records, rather than constructing a complete indented string and its full encoded copy. Individual model records, including sections, still use the existing Pydantic serializer. This preserves the in-memory/public extraction contracts and avoids a broader trace migration.

The reader checks format version, bounded expanded length, gzip integrity, content checksum, root identity consistency, Pydantic contracts and the evidence graph. The expanded limit is 256 MiB; exceeding it fails explicitly before publishing a new source-map artifact. This operational limit needs reevaluation for larger future corpora. SHA-256/CRC detect corruption, not malicious authorized rewriting or clinical truth.

The writer atomically creates a new artifact and refuses to overwrite by default. Explicit `overwrite=True` is used only at the existing pipeline persistence boundary to retain its established semantics and upstream directory guards. No pipeline run against existing review packages was performed. Existing files were not migrated or replaced.

## 3. Read-back and compatibility

Use `src.evidence_storage.load_source_map(path)` for persisted source maps. It reads both the new envelope and prior expanded JSON, including artifacts without an evidence sidecar. All 30 actual P1-A artifacts were read and graph-validated by this loader. A nested configuration key resembling the envelope marker is not mistaken for a storage envelope.

`SourceDocument.model_dump_json()` and `SourceDocument.model_validate_json()` retain their original expanded-model behavior. A caller reading the compressed payload needs the new loader; old third-party readers expecting the complete expanded JSON root cannot read new envelopes without adapting. Root document/hash metadata remains directly readable, and the existing pipeline hash reader is tested unchanged. This is backward read compatibility with old artifacts, not forward compatibility for old software reading the new storage format.

Normal and failure persistence paths both use the new writer. The five clinical content fields, generation input, reference selection, Azure provider implementation, clinical validators, human-review gates and original source/checkpoint identities are unchanged. The storage format is internal review metadata, not a new production clinical schema.

## 4. Warning classifications and coverage policy

`EvidenceWarning` now carries a classification, optional supporting-basis text, native bbox and block ID in addition to its existing page/span/critical/resolved fields.

| Classification | Meaning and handling |
|---|---|
| `confirmed_missing` | Confirmed absence of native page text, not a claim about the unseen clinical contents. Unresolved records block complete coverage even if an erroneous boolean says `critical=False`. |
| `clinical_unresolved` | A table/figure mention, materiality-unreviewed non-whitespace transformation, or existing extraction blocker needs clinical/source review. Remains blocking. This does not establish that every removed paragraph is clinically material. |
| `possible_corruption` | Encoding/sign/unit, native reading order, extractor disagreement or unavailable geometry/inventory. Describes a possibility rather than asserting proven corruption; unresolved records remain blocking. |
| `unclassified_visual` | Native image/drawing geometry with unknown clinical/decorative relevance. Not labelled a proven clinical figure, and not marked `critical=True` merely for existing. Still prevents a complete-source-coverage claim pending classification. |
| `supported_nonclinical` | Requires an explicit supporting basis. A basis string alone does not independently verify the conclusion or resolve the warning: unresolved records remain blocking. No automatic decorative classification or new approval workflow was introduced. |
| `legacy_unclassified` | Prior warnings lacking the new field remain loadable. Existing critical flags remain blocking; their uncertain origin is not silently reinterpreted. |

No corpus drawing was automatically declared decorative. Native geometry alone cannot independently establish that a border, logo or plot is nonclinical. Supported decorative status must come from independently reviewed source evidence through the existing review boundary; this milestone neither fabricates that evidence nor grants approval.

Geometry now records image versus drawing inventory origin. Each unclassified visual warning has its own native page, bbox and block ID. Text-column detection excludes visual-only boxes, eliminating drawing-induced column signals without declaring text reading order verified. Encoding warnings identify the exact first problematic native span per candidate and explicitly say they are not an exhaustive glyph inventory. Deleted-text warnings point to the original source span rather than an empty target span.

Coverage reporting separates unresolved critical records, unresolved uncertain records, all classified warning records and affected pages. Both unresolved critical and uncertain records prevent `source_coverage_complete=True`. A nonclinical classification cannot clear a critical flag by itself. Clinical validation and mandatory human approval remain separate.

Generation batches gain `warning_dependencies` describing **source overlap** at owned-span, page or conservative document scope. Page association is traced to native source buffers where possible. Existing document-wide critical-ID metadata is preserved. `context_dependencies=[]` still has `dependency_status="not_planned"`; these warning associations are not concept planning, durable recovery or proof of causal dependencies. Section-map-only warnings are exposed with affected pages in coverage; generation planning continues to use native/canonical extraction evidence.

Observed unresolved classifications across this corpus: **1,176 clinical-unresolved, 517 possible-corruption and 2,474 unclassified visual regions**. No confirmed-empty native page or independently resolved decorative classification was established. All 30 documents still report incomplete source coverage even when every section is artificially marked processed.

Figure-evidence warnings now occur on 151 pages with figure evidence signals, rather than treating every visual inventory as a figure. Unclassified signals retain their own regions instead. Text-only reading-order warnings occur on 298 pages. Encoding warnings occur at 174 candidate locations; recording candidate-specific spans changes counts relative to P1-A's page-only warnings. Non-whitespace transformation warnings can deduplicate when two stages point at the same original deleted span; all 395,271 mappings remain retained.

## 7. Remaining review risks

Unclassified borders, logos, plot primitives and other drawings can still block complete coverage. That is a deliberate unresolved-materiality signal, not a diagnosis that each region is clinical. Some text-block column patterns, replacement glyphs in ordinary typography, bibliography/boilerplate deletions and extractor formatting differences also remain false-positive blocker risks. This milestone improves classification/location rather than deciding clinical materiality automatically.

Compression solves the dominant disk and transient serialization cost, not the full duplicated in-memory model. Load allocations remain substantial, serialization is slower, and external readers need the new loader. Reference-based lazy traces or further in-memory deduplication may be appropriate only after this persistence boundary is reviewed. Larger PDFs, concurrent jobs, cold-disk behavior, durability and real missing NEJM fixtures remain unverified.
